SecondHands Team Workflow

Six people, one repository, one Snapdragon laptop on Tailscale. This page says which folder each person owns, what passes between layers, how the laptop is shared without stepping on each other, and where every model comes from. The Wiki page Wiki/runbooks/team-workflow.md is the source of truth.

3 · Git

Collaboration rules

  1. Branch per person and topic: dm/session-screen, vp/qnn-backend. Small and short-lived.
  2. Before a pull request: the matching just test-* recipe, ruff check src, and for the UI bun run --cwd ui test and build.
  3. Pull request against main, link the plan task, one reviewer, merge early and often.
  4. Knowledge changes update the owning Wiki page plus a dated log entry in the same pull request. One task list: Wiki/plan.md.
  5. Never commit artifacts/, data/, weights, recordings, calibration files, personal names, or Windows account names.
  6. Check the next free SH-T- number before adding one; two parallel pull requests already collided once today.
4 · The shared laptop

One Snapdragon laptop, six people, no collisions

The laptop is a deployment and measurement target. Develop on your own machine; the laptop runs main plus the one branch under test. Reach it over Tailscale at qcworkshop27.tail2122cc.ts.net through Windows OpenSSH; the account name lives in the team chat, not in Git.

Morning, ten minutes

Who runs what on the laptop today and when the camera is needed. Write the camera schedule in the chat.

During the day

Branches and pull requests. The steward merges main onto the laptop at agreed times, not continuously, so no measurement is taken on a moving target.

Before the rehearsal

Freeze main, record the commit and .pte hashes and versions in the Wiki, stop merging.
