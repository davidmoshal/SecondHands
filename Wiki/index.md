# SecondHands Wiki

**Our stream: Compute Track.** [Hackathon developer guide](https://github.com/aaishikasb/qc-executorch-guide) · [Compute rules and technical summary](hackathon-compute.md)

[Judging criteria](hackathon/judging-criteria.md) records the five criteria and their 100-point allocation from the attendee-guide photograph supplied on 2026-10-17.

This Wiki holds maintained project knowledge. **Current direction (2026-10-17):** the project is a camera-based fitness tracker; start with [the movement tracker tech stack](design/tech-stack.md). [The earlier proposal](proposal.md) describes the previous assistive-control idea and is being updated; see [Project direction](project.md) for decisions and evidence gaps.

## Plan and experiments

- [System design](design/index.md) — the implemented exploration dashboard and trigger policy, remaining proposals, and PyTorch/ExecuTorch runtime boundaries.
- [Use cases and team ownership](use-cases.md) — the clinician-owned test-protocol principle, the use-case catalog from clinical assessment to field sobriety support and private skin screening, the protocol template, proposed ownership, reach to phones, and the privacy rules.
- [Movement tracker tech stack](design/tech-stack.md) — the proposed camera-based fitness tracker stack for the Snapdragon laptop: sensing, pose estimation, ExecuTorch runtime tiers, interface contract, team document map, and two-day plan.
- [Field sobriety example](requirements/field-sobriety.md) — an example of watching walk-and-turn and one-leg-stand movements with the same pose pipeline. It does not replace the fitness tracker and it does not determine impairment.
- [On-device advantages](requirements/on-device.md) — the team's reasons for keeping the camera and inference on the machine: private medical-test images stay local, and the camera still works with no network.
- [Skeletal medical tests](requirements/skeletal-medical-tests.md) — ten candidate mobility tests a body-pose camera can time, count, or measure, including balance, gait, and sit-to-stand. The list does not select a protocol or claim a diagnosis.
- [Development setup](project.md#development-setup) — Python and React package responsibilities and observed setup verification.
- [MS-09 / Femto Bolt bridge setup](setup/ms-09-femto-bolt-bridge.md) — why a local Snapdragon depth bridge was built, recorded depth/person tests, launch instructions, and remaining reliability limits.
- [Team workflow](runbooks/team-workflow.md) — project structure, separation of concerns with owners, Git collaboration rules, sharing the one Tailscale-connected Snapdragon laptop (steward, camera ownership, ports, environments), and the model acquisition and ExecuTorch-status table.
- [Mac and Snapdragon development](runbooks/mac-and-snapdragon-development.md) — local setup, sharing changes through Git, running PC commands through T3, and dependency limits.
- [Task plan](plan.md) — checkbox tasks grouped by Mac setup, models, recognition features, UI, design/ExecuTorch, comparison, Snapdragon deployment, and demonstration phases.
- [Experiments before Saturday](experiments-before-saturday.md) — the proposed Mac comparison, test observations, measurements, division of effort, and Compute PC follow-up.
